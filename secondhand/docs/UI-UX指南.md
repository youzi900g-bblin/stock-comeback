# UI／UX 指南：選單與介面怎麼製作

這份文件整理選單與介面的做法，給子專案製作第一階段的畫面使用。內容分兩種來源：

- **有資料支持**：來自網路查到的平台文件與開發者文章，附來源連結。
- **本專案的提案**：根據系統設計提出的做法，標示為「提案」，由你決定是否採用。

查到的資料多是開發者部落格與平台文件，不是正式的 UX 研究，採用時請當作方向。

## 一、製作流程

1. **列出畫面與動線**：先列出第一階段需要哪些畫面，以及玩家怎麼從一個畫面到另一個畫面。
2. **畫線框圖**：用方塊與文字畫出每個畫面的版面，不用顏色與美術。手機直式為主。
3. **定視覺風格**：決定邊框、標題列、字型、色票，做成一套可重複使用的元件。
4. **做元件**：按鈕、面板、清單、物品卡片、提示對話框。先做元件，再組成畫面。
5. **串起流程並實測**：在手機上實際點，找出看不懂、按不到、文字被截斷的地方。
6. **截圖確認**：每個畫面完成後，用手機直式寬度截圖給使用者看。

## 二、手機操作的基本規則

### 有資料支持

- **主要操作放在拇指容易碰到的地方**：螢幕下方的兩角是拇指區，主要操作放這裡（[Fortnite 手機設計文件](https://dev.epicgames.com/documentation/fortnite/designing-for-mobile-in-fortnite)、[Packt 手機遊戲設計](https://www.packtpub.com/en-cy/learning/how-to-tutorials/mobile-game-design-best-practices)）。
- **觸控目標不能太小**：Apple 的規範是按鈕至少 44×44 pt，最小也不能低於 28×28 pt（[Apple 遊戲設計規範](https://developer.apple.com/design/human-interface-guidelines/designing-for-games.md)）。
- **介面保持單純**：Fortnite 建議少而單純的介面，在手機小螢幕上才好操作。
- **最重要的選項放最醒目的位置**，帶玩家進入遊戲（Packt）。
- **高對比與色盲選項**：建議加入高對比設定，並用清楚的資訊層級（[Unity 手機 UI 設計](https://blog.unity.com/en/games/mobile-ui-design-best-practices-part-1)）。
- **多機型測試**：螢幕形狀差異大，要在多種裝置上測。

一份 arXiv 研究（18 位受試者）提到最舒適的拇指點擊範圍半徑約 27.5 到 41.3 mm（[論文](https://arxiv.org/pdf/2110.08753)）。樣本很小，只當參考。

### 提案：本專案採用

- 主導覽（衣櫃、手機市場、賣場、私訊）放在畫面下方，做成底部分頁。
- 「下一天」「上架」「確認」等主要按鈕放在右下角。
- 所有可點的東西至少 44×44 的 CSS 像素，之間留空隙，避免誤觸。
- 一個畫面只放一個主要動作，其他動作用較小的按鈕。
- 重要資訊（金錢、天數）固定在畫面上方。

## 三、像素風介面的做法

### 有資料支持

來源整合自 [Defold 論壇](https://forum.defold.com/t/gui-for-pixel-art-games-heres-how/77704)、[Godot 4.4 像素風設定](https://itch.io/blog/806788/godot-44-settings-for-pixel-art)、[Kirupa 像素美術教學](https://www.kirupa.com/hodgepodge/preserving_pixel_art_aesthetics.htm)，皆為社群與部落格文章，請自行驗證。

- **整數倍縮放**：介面與美術都以整數倍放大，不要使用非整數的縮放，否則像素會變形。
- **關閉平滑**：使用最近鄰（point）縮放，不要使用雙線性或雙三次。網頁中對應的設定是 `image-rendering: pixelated`。
- **字型**：像素字型只用它原本大小的整數倍，例如 8px 的字型只用 8、16、24。不要加抗鋸齒或陰影，全介面使用同一個像素字型。
- **9 切片（9-slice）**：面板與按鈕用 9 切片，邊框保持清晰，中間可以伸縮，適合內容長度不同的視窗。
- **以原生解析度設計**：邊框、按鈕、圖示在遊戲的原生解析度下畫好，不要個別放大。
- **可讀性**：輪廓清楚、間距一致、色數少，避免 1 px 的細線。

### 提案：本專案的字型

`stock/game/fonts/` 裡已有 Cubic_11（有附授權檔）。是否沿用，請由你決定，並先確認授權條件。

### 提案：舊電腦視窗的質感

系統設計的方向是「介面與背景用 PS2 風、舊式電腦視窗的質感」。具體做法：

- 面板做成視窗：頂端有標題列、右上有縮小與關閉的小方塊，邊框有立體感（亮邊在左上、暗邊在右下）。
- 按鈕有「凸起」與「按下」兩個狀態。
- 主畫面（手機）可以做成一支小手機或舊電腦桌面，社群與賣場是裡面的視窗或應用程式。
- 色彩沿用背景的柔和色（淡紫、粉、淺藍），避免純白與純黑。
- 提示對話框用小視窗，不用全螢幕遮罩。

## 四、本遊戲的畫面清單（第一階段，提案）

| 畫面 | 主要內容 | 主要動作 |
| --- | --- | --- |
| 創角 | 名字、髮型、膚色、個性標籤 | 完成 |
| 主畫面 | 金錢、天數、角色與房間 | 進入衣櫃、進入賣場、下一天 |
| 衣櫃 | 物品清單、分類、容量 | 對每件選「賣」或「留」 |
| 上架標價 | 物品圖、基礎價值、市場價、標價輸入、預計等待天數 | 確認上架 |
| 賣場 | 已上架物品、掛賣天數、狀態 | 改價、撤下 |
| 每日結算 | 當日成交、金錢變化 | 進入下一天 |

第二階段才會加入：手機市場（社群）、私訊（議價與 NPC）、包貨出貨。

## 五、各畫面的做法

### 1. 衣櫃與物品清單

- 網格或清單：資料顯示的建議是 20 件以下可用 4×5 或 5×4 的網格；需要排序與比較時，清單更合適，可以用欄位標題依名稱、類型、價值排序（[Abratabia 物品欄 UI](https://www.abratabia.com/game-ui-design/inventory-ui.php)、[Strayspark 物品欄文章](https://www.strayspark.studio/blog/inventory-crafting-system-players-enjoy)）。
- 同一份資料可以切換網格與清單兩種顯示。物品變動後要重新顯示，並保留捲動位置（[Unreal 說明](https://opsive.com/?p=20051)）。
- 資料多為部落格，不是正式研究，請在實測後決定。

提案：
- 第一階段只有幾件基本款，用網格。第二階段物品變多時，再加清單與排序。
- 每張物品卡片顯示：圖、名稱、風格標籤、基礎價值。點開後才看詳細資料。
- 容量用「已用／上限」顯示，例如 18／20，快滿時用醒目顏色。
- 「賣」與「留」做成兩個明確的按鈕，不要藏在選單裡。

### 2. 上架與標價（本遊戲最核心的畫面）

提案：
- 同時顯示三個價格：基礎價值、市場價、玩家標價。並排在同一列，用不同顏色區分。
- 標價用滑桿或加減按鈕調整，不要讓玩家只靠鍵盤輸入數字。
- 即時顯示預計等待天數，隨標價變動，讓玩家看到「標得越高，等越久」。
- 標價遠高於市場價時，用文字提示，不要彈出視窗打斷操作。

### 3. 賣場

提案：
- 清單顯示每件物品的掛賣天數。超過 5 到 10 天（待定）沒成交時，在該列顯示小提示與「改價」按鈕。
- 提示是建議性質，不強迫。

### 4. 手機市場（第二階段）

提案：
- 做成動態牆，每則貼文顯示圖、賣家開價、與市場價的比較（便宜、接近、偏貴）。
- 每天約 5 次刷新，剩餘次數在畫面上方顯示。
- 買下前顯示確認，內容是「開價、市場價、買後能賺多少」。

## 六、教學與新手引導

### 有資料支持

- **逐步、在情境中教**：Apple 的遊戲新手引導建議逐步、在實際情境中教學，不是一次講完；與提早目標無關的功能，等玩家完成引導後再介紹（[Apple Onboarding for Games](https://developer.apple.com/app-store/onboarding-for-games/)）。
- **引導要快、有趣、可選**，並在設定或說明區留一個重看的入口（[Apple 引導規範](https://developer-rno.apple.com/design/human-interface-guidelines/patterns/onboarding)）。
- **做中學，不要塞文字**：用動作與視覺提示取代大段文字（[UX Planet](https://uxplanet.org/mobile-onboarding-interact-don-t-tell-f0c35da2b2b4)、[Wayline](https://www.wayline.io/blog/ux-game-tutorials-player-retention)）。
- 某些網站的留存率數字沒有標明來源，本文不採用。

### 提案：對應系統設計的教學

與 `系統設計.md` 的新手教學一致：

1. **第一步**：只教賣一件衣物。引導玩家選一件、標價、上架、等待、成交、拿到錢。一次只亮一個要點，其他按鈕先淡出或停用。
2. **第二步**：第一次成交後，才介紹基礎價值與市場價，之後逐步帶入標籤與流行。
3. 教學用高亮與箭頭指向要點擊的東西，文字限一兩句。
4. 玩家可以跳過，設定裡有「重看教學」。

## 七、狀態與回饋

提案：
- 每個按鈕有三個狀態：一般、按下、停用，停用時要說明原因（例如「衣櫃已滿」）。
- 金錢變動用數字跳動或短暫的顏色變化，讓玩家知道結果。
- 成交、買進、容量已滿等事件用小提示，不用全螢幕對話框。
- 空狀態要有說明，例如「衣櫃是空的，先去市場逛逛」。

## 八、檢查清單

- [ ] 手機直式寬度可以操作，沒有橫向捲動。
- [ ] 可點的東西至少 44×44 CSS 像素。
- [ ] 主要按鈕在下方、拇指能碰到的位置。
- [ ] 字型只用整數倍放大，沒有模糊。
- [ ] 圖片使用最近鄰縮放，邊緣清晰。
- [ ] 面板用 9 切片，文字變長時不破版。
- [ ] 每個畫面只有一個主要動作。
- [ ] 教學一次只教一件事，可以跳過，可以重看。
- [ ] 重要數字（金錢、天數、容量）固定可見。
- [ ] 色彩對比足夠，有高對比選項的空間。
- [ ] 實機截圖確認，每個畫面都看過。
